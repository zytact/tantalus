# Proxy hubs

Settings lists CLIProxyAPI hubs under `Proxy hubs`. `Add hub` opens a form with `Hub URL`, `Management key`, and an optional `Label`. The main process reads a new hub before saving it, so a URL or key that does not work is never saved and the form shows the cause. The saved key stays in the main process, so an edit starts with the key blank. A blank key keeps the old one only on the same URL origin; a different origin requires re-entry. A new URL or key is read again before saving; a new label alone is not. Show and Hide management key control only the value being typed.

Each hub row has a `<label> proxy hub` switch, `Edit <label>`, and `Remove`. A switched-on hub gets its own allowance section after the direct providers, with one block per pooled Codex or Claude account showing provider and plan, and its own tray block. Email buttons identify accounts by `<hub> <Provider> account <n>`. Opencode hub accounts are unsupported. A saved hub that contains Codex or Claude switches off the matching direct provider and shows a toast. Trying to enable that direct provider shows a toast asking you to remove it from the hub first. A saved hub keeps blocking its providers while switched off. Remove the hub, or remove the provider from it and refresh its roster, to release the direct provider. The dashboard hub URL link opens the hub URL followed by `/management.html` in the browser. A hub that refuses its key stops being read until it is switched off and on again or successfully edited with a working URL/key. Each hub account learns its own pace, apart from the direct provider.

## Preview proof

On `--mock ready`, open Settings, click `Add hub`, then `drive.ts fill textbox "Hub URL" http://127.0.0.1:<fixture port>` from `fixture.port` in the run directory, `fill textbox "Management key" fixture-management`, and `fill textbox "Label Optional" "Fixture hub"`. Click the form's `Add hub`. Settings must list `Fixture hub` with its switch on, and Allowance must show a Codex Pro and a Claude Max 5x account. Confirm both direct switches turn off with a toast, and trying either one again leaves it off with a removal message. Confirm the dashboard hub URL points at the fixture host and `/management.html`. Switch the hub off and confirm the direct providers stay blocked, then remove it and confirm the direct providers can be enabled. Edit the label with the key blank and confirm it saves without a hub read. Try a different URL origin with the key blank and confirm the form asks for the key again. Restore the label, then try adding another hub with a wrong fixture key; its error must show the refusal and it must not be saved. Cancel the form and click `Remove` before teardown.
