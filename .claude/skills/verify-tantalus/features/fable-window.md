# Fable window (7 days)

Some Claude plans cap Fable on its own each week. The main process reads the entry in the usage response's `limits` array whose `kind` is `weekly_scoped` and whose `scope.model.display_name` is `Fable`, and maps its `percent` and `resets_at` into the Fable window. A scoped cap on any other model is ignored. Claude hub accounts read the same endpoint and use the same mapping. Codex and Opencode have no Fable cap.

The Claude card shows it after the Long window as `Fable window`, `7 days`, with the remaining headline, a progressbar named `Fable window remaining`, the time-based pace label and marker, Resets in, At, and Used. It learns its own pace like any other window (see `pace.md`): its logs are keyed `claude:fable` and `["usual","claude",<tier>,"fable"]`, apart from the Long window's `604800`, and its Settings row reads `Fable window`. Local activity cannot tell which model a Claude session uses, so Fable counts as in use only while its own stretch is open, and its tortoise goes only by its own ticks. The tray has no Fable row and the tray number ignores it. A spent Fable window leaves the status `Live`, since other models still work. An account without a Fable cap shows no Fable window.
