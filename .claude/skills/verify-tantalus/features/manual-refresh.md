# Manual refresh

Refresh invokes the `refreshUsage` command for every enabled direct provider and hub. Once a refresh has run for 200 ms, the button becomes disabled, reads `Refreshing`, and sets `aria-busy=true`, so a fast answer never flashes the busy state. Once shown, that feedback lasts at least 400 ms. Repeat clicks are ignored from the start. Ctrl+R and Cmd+R use the same action, including from Settings and the remote access page, though the busy button is out of view in Settings. Refresh now in the tray calls the same main-process path.

The main process reads enabled direct providers and hubs concurrently, and each one appears as soon as its own read lands, so a slow hub does not hold back direct readings. Only a saved hub whose roster is not known yet makes direct reads wait, because it may own a direct provider. Each hub account reads its plan, subscription, and credits alongside its usage. Disabled direct providers stop before credential reads; hub account reads are independent of direct switches. Hubs support Codex and Claude, not Opencode. A refresh asked for mid-read folds into one more pass, and both callers get its result. A direct provider or hub account failure after prior success keeps figures and shows Cached. Missing direct credentials before any success show Not signed in. Other first failures show Could not refresh. Management-access rejection clears the hub's accounts, shows Access refused, and excludes it from later refreshes until re-enabled or successfully edited.

## Preview proof

In Tantalus Preview on `--mock ready`, enable Opencode and add the fixture hub per `proxy-hubs.md`. Activate Refresh and capture the busy state when practical, then capture the completed window. Confirm the timestamp and each account status. Repeat through the keyboard shortcut and tray Refresh now. Switch to `error` and Refresh: all five account readings keep their figures and read `Cached`; the fixture's hub heading stays Live because account listing still succeeds. `launch.sh --mock error` fails the very first direct read, so it shows `Could not refresh`. For isolated auth-missing proof, use real-mode launch with empty `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, and `XDG_DATA_HOME` directories. Mock launch supplies its own fixture credentials and overrides these variables.

To prove direct readings do not wait for a hub, keep Opencode and the fixture hub, switch to `error` and Refresh so Opencode reads `Cached`, then switch to `hub-slow` and Refresh. Three seconds later Opencode must read `Live` while the hub accounts still read `Cached` and the button reads `Refreshing`. In `fixture-requests.log`, `/zen/go/v1/usage` lands in the same second as the first hub requests, and each hub account's `HUB` lines (usage, profile or subscription, credits) share one timestamp, so the whole refresh takes one 6-second hub round.
