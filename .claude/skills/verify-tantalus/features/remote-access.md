# Remote access

Settings has two switches below Open at login, then the paired devices list. Both start off and save to `remote-access.json` in the settings directory. Nothing listens while both are off.

**Local network** makes the main process listen on `0.0.0.0` at the identity's web port, 4748 for the preview. The row lists `http://<address>:4748` for every non-internal IPv4 address, which includes the Tailscale address when Tailscale is up. **Tailscale** alone listens on `127.0.0.1` at the same port and runs `tailscale serve --bg --https=8444 http://127.0.0.1:4748`; with both switches on, the listener remains on `0.0.0.0`. The row shows `https://<machine>.<tailnet>.ts.net:8444`, read from `tailscale status --json`. Switching Tailscale off runs `tailscale serve --https=8444 off`. Each listed URL has a QR button that shows a scannable code for that URL below it. Tailscale keeps the route in its own config, so it survives a quit, and launch attempts `serve` again when the switch is saved on. Confirm the HTTPS URL after restart, since a saved switch alone does not prove Serve succeeded.

A change saves first, then listens, then runs Tailscale. If any step fails, the file and listener go back to how they were, the switch stays put, and an alert names the cause, such as `Port 4748 is already in use.` or `Tailscale is not signed in.` If the port is taken at launch, the saved switches stay on and Settings shows `Remote access is not being served. Port 4748 is already in use.` until the next successful change.

Only paired devices read usage. The built page's files are public, but `/api/events`, `/api/current/*` and `/api/refresh` answer 401 without a paired device's cookie, and an unpaired browser shows a **Pair this device** form instead of the allowance view. Below the two route rows, **Paired devices** has a **Pair a device** button. It shows a 6-character code with a countdown from 5:00 and swaps the button for **Cancel**. The code lives only in memory. It pairs one device, expires after 5 minutes, and is withdrawn with a toast after 5 wrong attempts. `POST /api/pair` with `x-tantalus-action: pair` and `{"code": "..."}` answers 204 with an HttpOnly, SameSite=Strict cookie named `tantalus-4748` for the preview, or 403 `That code is wrong or has expired.` The device is named after its user agent, such as `Chrome on Linux`. Each paired device gets a row reading `Connected` while it follows usage, otherwise `Last seen ...` or `Not seen yet`, with **Rename** and **Remove**. `paired-devices.json` in the settings directory holds each device's id, name, times and a SHA-256 hash of its token, never the token. Remove ends the device's open stream at once, and the browser falls back to the pairing form. Pairings survive switching the routes off and on.

The page is the allowance view without Settings or allowance notices. It includes enabled direct providers and every enabled hub's Codex and Claude accounts; Opencode hubs are unsupported. It follows `/api/events` and then reads `/api/current/usageSnapshot`, so a publish during load is not lost. It also reads `/api/current/serverEpoch` for countdowns. The event stream sends the current snapshot on connect and one more on every publish. Refresh posts to `/api/refresh` with `x-tantalus-action: refresh`; a POST without that header returns 405. Other resources only serve GET. A Host header that is not an IP address, a single-label or `.local` name, or a `ts.net` name gets a 403, and a path outside the built page gets a 404.

## Preview proof

Launch with `--mock ready`, enable Opencode, and add the fixture hub per `proxy-hubs.md`. Open Settings and switch Local network on. Confirm the addresses, `{"localNetwork":true,"tailscale":false}` in `mock-home/config/dev.arnab.tantalus.preview/remote-access.json`, and a listener on `0.0.0.0:4748`. Show each address's QR code, screenshot it, and decode the image, which must return that address exactly. Load one listed address with `drive.ts --web` and confirm the pairing form. Click **Pair a device**, read the code from a snapshot of the window, then `drive.ts --web <url> submit textbox "Pairing code" <code>`. Each `--web` command loads a fresh page, so typing and submitting must happen in that one command. The `--web` profile keeps the cookie until cleanup. Confirm the device row reads `Connected` while a `--web` command holds the page open, the code row is gone, and `paired-devices.json` holds no token. Confirm Opencode and both hub accounts render with Refresh but no Settings or notices. Adding the fixture hub switches direct Codex and Claude off. Before adding it, confirm all three direct providers render. Both states show remaining headlines and Used facts, matching the preview window. For curl, pair a second device with a fresh code: `curl -si -X POST -H 'x-tantalus-action: pair' -d '{"code":"<code>"}' http://127.0.0.1:4748/api/pair` prints the `set-cookie` line, and later requests pass it as `-H 'cookie: tantalus-4748=<token>'`. Keep the token out of evidence. Without the cookie, `/api/current/usageSnapshot` returns 401. After setup refreshes finish, start a bounded SSE observer with `curl -sN --max-time 30 -H 'cookie: ...' http://127.0.0.1:4748/api/events`, complete two sequential remote refreshes, then stop the observer. Expect the initial event plus two refresh publications; background work can add events. Remove the curl device while the observer runs. The stream ends at once and the next request returns 401. Try five wrong codes against a fresh code and confirm the toast and that the right code then fails. Probe with curl: `-H 'Host: evil.example'` returns 403, `--path-as-is /../package.json` returns 404, and POST to a page resource or Refresh without the action header returns 405.

For Tailscale, save `tailscale serve status` first and confirm nothing is on 8444. Switch Tailscale on, confirm the `ts.net` URL and the route to `127.0.0.1:4748`, and load that URL with `drive.ts --web`. Switch both off and diff `tailscale serve status` against the saved copy. This needs Tailscale installed, signed in, with Serve and HTTPS allowed on the tailnet, and on Linux an operator set with `sudo tailscale set --operator=$USER`. Without those, record the alert the switch shows instead.

To prove rollback, hold the port with a Python socket bound to `0.0.0.0:4748`, then switch Local network on. The switch stays off, the alert names the port, and the file is unchanged. To prove persistence and the launch message, switch both routes on and run `launch.sh --restart`. Both stay on, the listener returns, and the route is still there. Then stop the preview's recorded pid, bind the port again, run `launch.sh --restart`, and open Settings to read the launch alert. Free the port, and switch any route to clear it. Leaving Tailscale on is safe, since `cleanup.sh` removes the preview's route.
